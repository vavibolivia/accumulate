# 야간 무인 운영 검증 계획 (2026-11-14 밤 ~)

사용자가 PC 를 켜 둔 채 자리를 비움. 5분마다 깨어나 아래를 점검하고, 문제가 있으면 고치고, 개선점이 보이면 구현한다.
점검 기록은 `verify-log.md` 에 시간순으로 남긴다 (아침에 읽을 수 있게).

## 목표 (아침까지 돼 있어야 하는 것)
1. 앱 창이 **보이는 상태**로 떠 있고 응답한다 (트레이로 숨지 않음, 오류 창 없음).
2. 계산 서버(java)가 계속 돌며 **모든 현물 페어 × 2017년부터** 1분봉을 받아 순위를 낸다.
3. 순위가 나오는 대로 **일별 집계**가 자동으로 돌아 `daily_agg` 에 종목별 하루 한 줄이 쌓인다 — USDT 환산 포함.
4. DB 가 깨지지 않고, 디스크가 바닥나지 않는다.

## 매 5분 점검 (verify-status.ps1)
| 항목 | 정상 | 이상 → 조치 |
|---|---|---|
| app 프로세스 | 살아 있고 responding, window=visible | 죽음 → error.log 확인 후 재실행. HIDDEN → 코드 원인 조사(트레이 숨김 경로) 후 재실행 |
| server java | 1개, 앱이 부모 | 없음 → 앱 로그 확인, 앱 재실행. 2개 이상 → 고아 프로세스 정리 |
| health | `ok · …` | FAIL 이 2회 연속 → 서버 멈춤으로 보고 앱 재실행 |
| ranking | coins 수가 늘거나 유지, generatedAt 이 10분 안 | 30분 넘게 그대로 → 서버 로그(앱 화면 하단) 확인 |
| db daily rows | 순위가 나온 뒤 6시간 주기로 증가, usd_rate null 은 환율 없는 호가(비USDT 중 일부)만 | consistency violations > 0 → 집계 로직 버그, 즉시 조사 |
| error.log | 없음 | 새 줄 → 스택 확인, 재현 테스트 작성 후 수정 |
| disk | 여유 20GB 이상 | 10GB 미만 → 사용자에게 보고(수집 기간 줄이기는 사용자 결정) |
| 메모리 | app < 1.5GB, java < 3.5GB(-Xmx3g) | 계속 증가 → 누수 의심, 원인 조사 |

## 코드 변경 규칙 (무인 중)
- 변경 전후 `dotnet test` 통과 필수. 실패하면 되돌린다.
- 앱 재시작은 서버 수집을 끊으므로(월 파일 단위로 이어받음) **버그 수정이거나 재시작 비용이 낮을 때만**. 개선은 모아 두었다가 한 번에.
- 사용자 결정이 필요한 것(디스크 정책, 서버 소스 없는 기능)은 손대지 않고 verify-log 에 "아침에 물어볼 것" 으로 남긴다.
- 파괴적 작업 금지: 데이터 폴더·DB 삭제, 설정 초기화.
